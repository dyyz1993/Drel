How the pieces fit together

Your app, the gateway and the push relay are three separate things. The app never depends on either of the other two — the gateway only provides app identity, and the relay only delivers a wake-up.

Your app and the push service are independent

Your app is a web page on any static host. A push service only delivers a wake-up. A gateway and a push relay may share one host, one domain and one certificate, or run entirely apart — see Self-host Drel for both deployment topologies.

Security model in one minute

A push address is a bearer capability. Keep it out of screenshots, logs, source control, and public URLs. The official delivery service processes requests to deliver them; it is not an end-to-end encrypted secret channel. Do not put credentials, recovery codes, or financial secrets in a notification payload.

What Drel does not do

  • A remote page does not receive native Bridge, camera, file, photo-library, clipboard, or approval powers merely because it opened in Drel.
  • A Web App Manifest alone does not make a page an offline app. Durable offline launch requires a verified package and a user-initiated install.
  • A successful API response means the relay accepted the request for APNs delivery; it is not a guarantee that a particular device displayed it.
