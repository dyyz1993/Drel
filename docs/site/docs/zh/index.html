从一条推送地址开始

Drel 提供推送接口，也为已签名的可信网页提供受控原生能力。这是两个独立接口：发送推送不需要 Bridge，推送本身也不会授予网页权限。

1. 获取地址与发送通知

在 Drel 首页复制“你的推送地址”，形如 https://api.drel.app/<YOUR_DEVICE_KEY>。地址就是向你的设备发送通知的凭证，不要提交到仓库、截图或公开日志。

把下列占位地址换成自己的地址；执行命令会实际发送一条通知：

DREL_PUSH_URL='https://api.drel.app/YOUR_DEVICE_KEY'
curl --get "$DREL_PUSH_URL" \
  --data-urlencode 'title=Build complete' \
  --data-urlencode 'body=Your build is ready'

也可以使用 JSON；命令中的 YOUR_DEVICE_KEY 是占位符，先在私有环境中替换：

curl https://api.drel.app/push \
  -H 'Content-Type: application/json' \
  -d '{"deviceKey":"YOUR_DEVICE_KEY","title":"Build complete","body":"Your build is ready"}'

仅打开不带消息参数的个人地址可查看发现信息；追加标题、正文或填写推送字段会触发发送。请求成功不等于用户已看到通知。详见 Push API。

2. 版本与能力

推送协议与 iOS App 版本分别演进。下面是已核对的版本边界；安装包、签名清单和用户授权共同决定实际可用能力。

能力最低 Drel 版本条件
Bark 兼容推送、打开 HTTPS 页面1.4.x个人地址；无需网页 Bridge
haptic、vibrate、share、fullscreen、clipboard、getLocation、addToHomeScreen1.5.0签名清单声明和可信来源；132 起受控动作均需前台用户操作
sensors 加速度与陀螺仪1.5.0（130 起）130 为声明式；131 起需用户同意且可撤销；132 起要求前台点击
audioLevel 实时音量1.5.2（TestFlight 138）签名声明、用户点击、Drel 与 iOS 麦克风授权；正式商店可用性以商店版本为准

audioLevel 返回 0–1 的音量值，最高 30 次/秒，不提供原始音频或录音文件；它不是实时语音识别或翻译。Bridge 完整参考 · Action Demo。

3. 在网页中调用 Bridge

在受信任应用的签名清单中逐项声明 capabilities_v2、用途和准确 origin。声明不等于授权；敏感动作只能在前台由用户操作触发，并等待成功回调后继续。

button.addEventListener('click', async () => {
  if (typeof window.BarkBridge?.callNative !== 'function') return;
  try {
    const result = await window.BarkBridge.callNative('clipboard', { action: 'read' });
    if (result?.success !== true) return; // 用户取消或授权失败
    // 只有成功后才继续处理 result
  } catch (error) {
    // 展示失败原因或提供普通浏览器替代方式
  }
});

位置声明使用 getLocation；旧清单中的 location 是兼容别名，JavaScript 动作名仍为 getLocation。普通网页不要假设拥有受控原生权限。

5. 调试与安全

  • 普通浏览器先做标准 Web 功能，Bridge 缺失、拒绝或取消时提供降级。
  • 传感器和音量订阅不在后台持续采集；离开、撤销或停止时关闭。
  • 不要把密钥、设备推送地址、用户位置或录音写进公开示例、Schema、截图或日志。
