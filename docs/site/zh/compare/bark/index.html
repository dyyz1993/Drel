寻找 Bark 替代方案？

Drel 可以接收来自脚本、CI 和自动化工具的 iPhone 推送通知，支持常见的 Bark 风格 HTTP 请求。点击通知后，可以在 Drel 内打开对应的 HTTPS 网页。建议先验证一个脚本，再逐项检查实际使用的通知参数。

English

Drel 和 Bark 有哪些共同点？

Bark 是开源的 iOS 推送通知应用，官方文档提供 GET、POST 以及标题、正文、URL、分组、声音等参数。Drel 也支持基础的 Bark 风格请求，可以从已有的构建提醒、脚本通知和监控消息开始尝试。

Drel 是独立产品，与 Bark 没有官方关联或背书。本页说明 Drel 已公开的推送接口，不代表所有 Bark 功能、客户端行为和第三方集成都能直接互换。

按使用场景选择

  • 需要给 iPhone 发送自定义提醒：结合 Bark 官方文档与 Drel 推送 API核对所需功能。
  • 需要点击通知后在 Drel 内查看报告或仪表盘：通过 url 传递 HTTPS 地址，参阅网页容器文档。
  • 需要安装可离线打开的网页内容：参阅 Drel 的离线包规范。实时接口数据仍可能需要联网。

如何迁移一个 Bark 风格推送脚本？

  1. 从 App Store 安装 Drel，启用通知并复制 Drel 生成的推送地址。
  2. 在测试脚本里换成 Drel 的服务器地址与密钥。Bark 的密钥和设备注册信息不能直接沿用。
  3. 对标题和正文进行 URL 编码，再验证通知收到后点开的是目标页面。
curl 'https://api.drel.app/YOUR_DREL_KEY/Build%20complete/Open%20report' -G \
  --data-urlencode 'url=https://tools.example/release/42'

推送地址包含发送权限，请勿把真实密钥写进公开仓库或截图。上方只有占位符，需要自行替换并运行才会发送通知。

切换前需要核对什么？

  • 按 Drel 参数文档逐项验证所需字段，不要默认加密格式、重要警报、音量控制或持续响铃与 Bark 完全一致。
  • 同时检查 HTTP 状态与响应正文；服务接受请求不等于手机已经显示通知。
  • 在真机锁屏状态验证通知，检查通知权限、专注模式和网络状态。
  • 自托管需要单独配置服务凭据与配对，请参考自托管服务指南。

可以继续使用 Bark 的密钥吗？

不可以，需要使用 Drel 生成的地址。这里复用的是基础 HTTP 请求的写法，不会迁移 Bark 的密钥、历史消息或设备注册信息。

尝试 Drel 前需要卸载 Bark 吗？

不需要，可以先发送独立的测试通知，验证后再修改生产脚本。
